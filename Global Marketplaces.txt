The root cause — when a session token expired, api.ts was auto-redirecting to /login. Now instead it clears the stale token and reloads the page, so the user continues browsing as a guest with the amber "Sign in" banner. The login page never opens without an explicit click.

What changed:

1. api.ts 401 handler — expired session now silently transitions to guest mode (token cleared, page reloads). No more window.location.href = '/login'.
2. /login page — if you already have a valid token and somehow land on /login, you're immediately sent to /opportunities instead of seeing the login form again.
3. /register page — same guard: authenticated users are skipped to /opportunities.

The full rule now:
- Guest browsing freely → login page never appears
- Token expires mid-session → guest mode silently, amber banner shows "Sign in"
- User explicitly clicks "Sign in" → /login opens
- User explicitly clicks "Start Pro / Register" → /register opens
